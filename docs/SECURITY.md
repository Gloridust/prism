# 安全说明

本文面向评估 Prism 是否适合自己场景的安全与运维负责人。字节级的设计见 [PROTOCOL.md](PROTOCOL.md)。

## 安全模型

Prism 假设网络上存在一个能力很强的审查方，能做到：

| 审查手段 | Prism 的应对 |
|---|---|
| 被动 DPI、TLS 指纹 | 外层是对自有域名的真实 TLS 1.3；客户端用 uTLS 模拟 Chrome 的 ClientHello；隧道首包没有任何明文特征 |
| 主动探测 | 没有凭据的访问者看到的是真实网站；steal 模式下整条连接被转发到真实的第三方站点；Noise 握手对没有 PSK 的对端不回任何字节 |
| SNI、证书封锁 | 自有域名 + 正规证书；可选 ECH 加密 SNI |
| TLS-in-TLS 识别 | 数据面不再套一层 TLS；每条流的前几个帧随机化长度 |
| 熵分析 | 高熵数据只出现在 TLS 记录体内 |
| 流量统计分析 | 长度整形、时序抖动、长连接多路复用、载波轮换 |
| 重放 | 一次性临时密钥 + 时间窗口 + 重放缓存 |

在终端侧，Prism 还防止三类常见的真实 IP 泄露：

| 泄露途径 | 防护 |
|---|---|
| DNS | 本地 DNS 代理，查询经隧道发出 |
| WebRTC / IPv6 | TUN 模式接管 IPv4 + IPv6 + UDP；代理模式写入浏览器 WebRTC 策略；路由器侧 STUN 规则前置 |
| 客户端崩溃后回落直连 | kill-switch：由系统防火墙执行，不依赖客户端进程存活 |

出口服务器默认拒绝隧道访问私网、环回和云元数据地址，防止持有凭据的客户端借它探测内网。

## 密码学

- 身份认证：服务器 X25519 静态密钥 + 每设备独立的 32 字节 PSK，双因子互认。
- 前向保密：会话密钥由双方临时密钥派生，服务器私钥日后泄露也无法解密历史流量。
- 两种握手：默认握手（80 字节首包，与随机数据不可区分），以及基于 [flynn/noise](https://github.com/flynn/noise) 的 Noise_IKpsk1（`handshake: "noise"`，**新部署建议使用**）。
- 数据加密：AES-256-GCM 或 ChaCha20-Poly1305，两者线格式一致，服务端自动识别。

## 已知局限

以下事项如实列出，部署前请评估：

1. **未经独立密码学审计。** 两种握手的构造与用法都没有经过第三方评审。面对高风险对手，请在上线前安排评审。请勿对外宣称 Prism “已审计”。
2. **未在真实审查网络中长期对抗验证。** 现有验证来自本地与 CI 环境，建议先做小范围试点并持续观察。
3. **自有域名可能被识别和封锁。** 域名与服务器 IP 不要与其他业务公开关联，并准备备用出口（`backups`）。
4. **QUIC 入口的客户端指纹来自 quic-go 而非 Chrome。** 对抗强的线路优先用 TCP 入口。
5. **浏览器策略的覆盖范围有限。** Safari、原生应用（Zoom、Teams、微信等）以及 Linux 上的 Edge 不受 WebRTC 策略约束，需要 TUN 模式。
6. **kill-switch 默认关闭。** 开机自动生效（`kill_switch_boot`）在 Linux 上经过真实重启验证；macOS 尚未在真机重启中验证，首次部署请实际重启一次确认。
7. **时钟依赖。** 两端时钟偏差超过 `window_seconds`（默认 120 秒）时无法建立连接，路由器需先完成 NTP 同步。
8. **uTLS 指纹需要跟随 Chrome 版本升级。**

完整的技术说明见 [PROTOCOL.md §9](PROTOCOL.md#9-安全局限与诚实告警务必读)。

## 合规

统一网络出口是正当的企业需求，但各地法规不同。请自行确认你的部署符合各运营地的法律法规与公司合规要求。

## 报告安全问题

发现漏洞请不要公开提交 issue，请通过仓库的 [Security](https://github.com/Gloridust/prism/security) 页面私下联系维护者。
